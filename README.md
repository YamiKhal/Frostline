# Frostline Worldgen v4 — Forge 1.20.1

Total overworld conversion. No vanilla biomes, no oceans, no rivers, no water,
no caves, no ores, **no trees of any kind**. 47 biomes across six regions.

Java does exactly **one** thing: a coordinate-aware density function, because
vanilla density functions can read Y, noise and splines but never X/Z position.
Everything else — terrain, surfaces, snow depth, biomes, decoration — is
datapack JSON generated by `gen3.py`.

Companion docs: `CONTROLS.md` (what to change, with line numbers),
`WORLDGEN.md` (the techniques and the guidelines behind them),
`HANDOFF.md` (paste-to-a-fresh-session context).

---

## 1. Regions

Seven biomes per northern region, split by terrain tier so a region is varied
without losing its identity. Tiers come from the same `erosion` value that shapes
the terrain, so a "peak" biome cannot land on flat ground.

| Tier | erosion | count | split by |
|---|---|---|---|
| Peak | −1.00 … −0.55 | 2 | weirdness |
| Crag | −0.55 … −0.375 | 1 | — |
| Rolling | −0.375 … 0.20 | 2 | humidity |
| Flat | 0.20 … 1.00 | 2 | humidity |

**1 Hollow Drifts** *(spawn, and the entire south to 5 000)* — `hollow_spires`
`windscoured_crags` `frost_shelf` `drift_barrens` `rime_hollows`
`frozen_hollow` *(spawn)* `snowveil_flats`

**2 Deadly Snowfields** — `frozen_spires` `glass_ridges` `shattered_shelf`
`deadly_snowfield` `crevasse_fields` `whiteout_flats` `bone_drifts`

**3 Ashen Wastes** — `cinder_ridges` `soot_spires` `slaghelm`
`ashen_snowfield` `ember_hollows` `ashfall_flats` `charred_barrens`

**4 Thawing Reach** — `slate_peaks` `tuff_spires` `grey_shelf` `slushfields`
`meltstone_hollows` `pale_flats` `gravel_barrens`

**5 Verdant Reach** — `emerald_bluffs` `verdant_crags` `mossy_shelf`
`verdant_downs` `sunlit_hollows` `verdant_plains` `sunlit_meadow`

**6 The Quiet** (12 biomes, 5 000 blocks compass south, never ends) —
`whisper_spires` `sculkspine_peaks` `hushed_shelf` `resonant_crag`
`creeping_downs` `vein_hollows` `bloom_hollows` `shrieker_fields`
`muted_flats` `still_barrens` `sculk_sea` `the_quiet`

### What changed from v3

- **`SnowDriftFeature` deleted.** Layered snow is now pure data — three placed
  features whose predicates measure distance from the nearest uphill face.
  §3 below, full rationale in `WORLDGEN.md §1`.
- **The Ashlands are gone**, replaced by **The Quiet** at 5 000 south instead of
  80 000. One material family instead of nine, graded by infestation rather than
  scattered.
- **The southern tail is region 1, not the Thawing Reach.** `south_cap` moved
  from `0.50` to `-0.70`, so region 1 runs unbroken from spawn to The Quiet.
- `gen3.py`'s hardcoded Linux output path is gone; it resolves relative to its
  own file and runs anywhere.
- `verify.py` added — ten static checks over the generated pack.

## 2. Progression

Two independent climate axes, each an instance of `frostline:progression`.

**Axis 1 — `temperature`.** `z_direction: -1.0` puts the payoff at compass north
(−Z).

| v | z (compass north) | Region |
|---|---|---|
| −1.00 | 0 | 1 Hollow Drifts *(spawn)* |
| −0.55 | 11 250 | 2 Deadly Snowfields |
| −0.20 | 20 000 | 3 Ashen Wastes |
| +0.15 | 28 750 | 4 Thawing Reach |
| +0.60 | **40 000** | 5 Verdant Reach |

Regions are contiguous bands tiling −1.00 → 1.00. Noise is a continuous field, so
reaching band 4 from band 1 requires physically passing through 2 and 3. Ordering
is a mathematical guarantee, not tuning. Border wobble is a low-frequency noise
summed onto the ramp in JSON — a monotonic ramp plus continuous noise is still
continuous, so ordering survives.

Compass south, `south_cap = -0.70` holds the value inside region 1's band
(−1.00 … −0.55) forever. **Region 1 therefore runs unbroken from spawn all the
way south** until the second axis takes over.

### The Quiet

A second instance of the same density function, in the `continents` slot, with
`z_direction: +1.0` and `south_cap: -1.0`, so it is pinned at −1 everywhere north
of spawn and ramps only southward. With `QUIET_RANGE = 6250` it crosses +0.60 —
the Quiet continentalness threshold — at exactly **z = +5 000**.

Quiet biomes claim continentalness 0.60…1.00; every other biome claims
−1.00…0.60. Since the Quiet axis is flat at −1 across the whole north, the region
cannot appear there.

**One material family.** Smooth basalt, blackstone, deepslate and obsidian are
the host rock; `minecraft:sculk` is the growth. All seven `q_*` palettes differ
*only* in how low the `frostline:infest` noise threshold sits before sculk wins —
`q_bare` at 0.82, `q_total` at −0.35. That single graded threshold is what makes
the region read as one organism spreading instead of twelve set-pieces.

**Coverage grades in three passes.** `sculk/crust` → `sculk/spread` →
`sculk/bloom` are the same `minecraft:sculk_patch` at rising `amount_per_charge`,
`growth_rounds` and `catalyst_chance`. Each biome runs exactly one, chosen by its
infestation stage (which rides the `humidity` axis). `sculk/veins` adds a
`multiface_growth` pass putting sculk_vein up walls and across ceilings — ground
cover alone never reads as invasive at eye level.

**It warps terrain, not just colour.** A `quiet_gate` (0 before the threshold, 1
inside, reaching 1.0 about 950 blocks early) feeds three things:

- `QUIET_SWELL` — ground sinks 0.055 and low organic mounds swell back out of it
- `FACTOR` drops by 1.4, floored at **1.6** — softened and undercut, still
  connected. (The old Ashlands used a 0.55 floor and risked floating debris.)
- `JAGGEDNESS` is multiplied by `(1 − gate)`, i.e. cancelled outright. Still
  means still.

No snow (`has_precipitation: false`), near-black sculk-teal fog, warped spores,
and soul-sand-valley ambience in the heaviest biomes.

## 3. Snow

v3 solved this with a Java port of Bedrock's snow-accumulation algorithm. v4
deletes that class, because Terralith achieves the same effect with no code at
all — and the data version is easier to tune.

**Java's `freeze_top_layer` places exactly one snow layer, always.** It drapes
terrain like a bedsheet, so every 1-block step stays a visible hard staircase.

The fix is three `minecraft:simple_block` passes placing 6–7, 4–5 and 2–3 snow
layers. The intelligence is entirely in each pass's `block_predicate_filter`,
which asks **how far am I from a block that stands higher than me**:

```
first  : a block from #frostline:drift_ground sits at my own Y in ring 1  -> deepest
second : nothing in ring 1, something in ring 2 (incl. diagonals)         -> medium
third   : nothing in rings 1-2, something in ring 3                       -> feather
```

"A ground block at my own Y" means that neighbour's terrain is one block higher
than mine — I am standing next to a step. So the passes are really "distance from
the nearest uphill face", and the layer count falls off with it. Snow **banks
against terrain steps and feathers away from them** instead of tracing them.

Two refinements over Terralith's version:

- **A block tag, not inline block lists.** Terralith repeats a three-block list
  in every predicate. `#frostline:drift_ground` holds all ~21 possible surface
  blocks once. Add a surface block to a palette → add it to the tag, or drifts
  ignore that biome. `verify.py` checks this.
- **Cliff-lip rejection.** A position whose neighbour's *lower* block is air is
  on the edge of a drop; drifts there would grow out into space.

Then `snow/fix` — a `random_patch` whose inner placement is an
`environment_scan` searching downward — catches anything sheltered under an
overhang that `freeze_top_layer` never saw.

Three profiles: `deep` (Hollow Drifts), `normal` (Deadly Snowfields, Ashen
Wastes), `thin` (Thawing Reach). Same machinery, different layer counts and
placement density. The Quiet and the Verdant Reach carry no snow passes at all.

Surface rules still place `snow_block` as ground material — the passes add graded
layers on top of it, not instead of it. And every palette keeps `steep` (cliff
faces) as **bare rock or ice**, because that exposed rock is what the drifts bank
against. Surface rules and layering are one system.

## 4. Trees

None. All tree features and configured features are deleted; `verify.py` fails
the build if any reference reappears.

To add your own dead trees later: configured features in
`data/frostline/worldgen/configured_feature/`, placed features in
`placed_feature/`, then add the placed feature id to **both** the biome's step-9
list *and* to `MASTER[9]` in `gen3.py`, in the same relative position. Features
sharing a step across biomes must appear in a consistent global order or the game
throws a feature-order-cycle error at world load.

Vanilla's `minecraft:tree` requires dirt-family ground, so snow-block surfaces
reject it silently. For leafless trees on snow use `minecraft:block_column` (see
the `*_needle` features for the pattern) or a custom feature that skips the
ground check.

## 5. Terrain

```
offset  = -0.50375 + spline(erosion -> spline(ridges_folded)) + 0.055*relief + quiet_swell
factor  = max(1.6, spline(erosion) - 1.4*quiet_gate)
jagged  = (1 - quiet_gate) * spline(erosion, ridges) * half_negative(noise(jagged,1500))
depth   = y_gradient(-64..320, 1.5..-1.5) + offset
sloped  = 4 * quarter_negative((depth + jagged) * factor) + old_blended_noise
final   = squeeze(0.64 * interpolated(blend_density(slide(sloped))))
```

| Terrain | erosion | y |
|---|---|---|
| flats | +1.0 | ~71 |
| plains | +0.6 | ~73 |
| rolling | −0.15 | ~84 |
| tier boundary | −0.375 | ~110 |
| crag | −0.72 | ~156 |
| peak | −1.0 | ~174, jagged tips ~212 |

Water removed at the generator: `sea_level: -64`, `default_fluid: air`,
`aquifers_enabled: false`. Caves removed twice over: nothing cave-related in
`final_density`, and `"carvers": {}` on all 47 biomes. Ores: `ore_veins_enabled:
false` and no ore features.

Deepslate and netherrack appear as terrain, not decoration: `slate_peaks` has a
raised deepslate line (y96→y152), `cinder_ridges` a netherrack/blackstone core
(y72→y140), and The Quiet has banded host rock from bedrock upward, so digging
into it never finds ordinary stone.

## 6. Building

```
python gen3.py        # regenerate all datapack JSON
python verify.py      # static checks
./gradlew build
```

`build/libs/frostline-1.0.0.jar` → `mods/`. JDK 17. **Create a new world** —
worldgen never applies to existing chunks.

`optional/structures/` holds biome tags for igloos, snowy villages, plains
villages (green region only), outposts and ruined portals; copy its `data/` over
`src/main/resources/data/` before building to enable. Off by default.

## 7. Tuning cheatsheet

Full version with line numbers in `CONTROLS.md`.

| Want | Change |
|---|---|
| The Quiet nearer/further | `QUIET_RANGE` (6250 → threshold at 5 000) |
| Region 1 to extend further south | same value — they are the same number |
| Verdant nearer/further | `NORTH_RANGE` on `PROGRESSION` |
| Payoff back at +Z | `z_direction: 1.0` on axis 1 **and** `-1.0` on axis 2 |
| Smaller biome patches | raise `xz_scale` on `VARIETY` / `EROSION` |
| Wilder Quiet terrain | the `-1.4` on `FACTOR`; drop the `(1 - QUIET_GATE)` on `JAGGEDNESS` |
| The Quiet more overgrown | shift every `infest` threshold in the `q_*` palettes down |
| Deeper snow | the layer tuples in `SNOW_PROFILE_IDS` |
| More exposed rock | raise the noise thresholds in the palette's `top` chain |
| Taller mountains | `ridge_spline(base, amp)`; +0.0078125 offset = +1 block |

`gen3.py` regenerates every JSON. Edit it, not the output.

## 8. Verification status

`verify.py` checks, across all 47 biomes: every file parses; every biome the
dimension references exists and vice versa; no two biomes occupy an identical
climate box; every per-step feature list is consistent with a single global
ordering (feature-order-cycle guard); every `frostline:` placed feature reference
exists on disk; no tree references anywhere; snow passes, `has_precipitation` and
the 0.15 temperature gate all agree; every biome has a surface rule and every
rule names a real biome; temperature, continentalness and erosion each tile
−1.00 → 1.00 without gaps; and every block a surface rule places on top is
present in `#frostline:drift_ground`. All pass.

v2 confirmed in-game that the progression codec, density chain, surface rule
tree, dimension and feature references all load on a real client. New in v4 and
therefore **unproven at runtime**:

- **The three-ring snow passes.** Each is 800 placement attempts per chunk. If
  chunk generation is slow, drop `tries` from 80 to ~40 in `SNOW_PROFILE_IDS`
  before touching anything else.
- **`minecraft:sculk_patch` and `multiface_growth` densities.** The counts are
  guesses, tuned blind.
- **`sculk/pillar`** — whether `block_column` cleanly caps a sculk column with a
  shrieker.
- **The Quiet's terrain warp** at the 5 000-south boundary.
